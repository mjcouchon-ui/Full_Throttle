PROBLEMS FOUND AND WHAT I DID
1. The baseline is OLDER code than main, not a copy of it (the colleague's assumption 13). Baseline has no hit-stop (ContactPause), no input buffer, no "FTBRAWL swing hit" line, no -brawlpolishqa in FTBrawlFighter.cpp, no "FT BRAWL won" line, and its log tap sees only "FT " lines (main's now also sees FTBRAWL, FTGameInstance.cpp:495). Consequence: before and after are different fights blow for blow, whatever the overhaul does. Fix: the header now says so, frames pair by moment, and each manifest has a new [summary] block (room up, boss enters, signature first time and count, Nova hurt counts, half-armor call, knock-outs, result with the "won kos= best= hits= time=" text) which is what to compare between the two builds.
2. 11_boss_hit could never exist on the baseline (it was anchored only on the "swing hit" Verbose line, which is main-only). Fix: same name, but on a build that logs neither "swing hit ... on boss" nor "weapon hit ... on boss" it is the last frame before "boss calls 3 more" (just after the blow that takes him to half armor). The manifest line says which anchor was used. The two sides are therefore not the same moment of the fight, only both "the boss just hit".
3. "FTBRAWL pose" and "swing hit" lines (main only) were mixed into [events], so any diff of the two manifests would have been flooded. Fix: pose lines go to their own [poses] section; swing hits are only counted, in a # line.
4. Career safety: nothing protected the player's career. FTUseTestSlot needs a race game mode, and UFTCareerSubsystem::Load saves ("New" or "Recovered", FTProgress.cpp:545, 609) on the default slot at every launch. Fix: -ftslot=pie on the command line (FTGameInstance.cpp:105; baseline :104), so anything loaded or saved is career_pie.
5. Raw-frame cadence was on a float knife edge: the game's timer does (ShotT += Dt) >= 0.2 with Dt = 1/60, which can come out as 12 or 13 frames. At 13 frames "2.0 s after the boss line" lands after his 2.2 s entrance has ended. Fix: in fixed-step mode the game is given a threshold half a frame below the wanted count (-brawlshotdt=0.19167 gives exactly 12 frames) and all offsets use frames/60.
6. Where the game was killed showed in the output: the [events] tail and the "newest frame" rule depended on the 3 s poll, so two runs of the same build could differ at the end. Fix: Get-BrawlEnd defines the film's last raw frame (3 s after "won" or boss + 20 s, plus two spare; or one frame after the knock-out that exceeds -MaxRetries) and the log is read only up to that frame for picks, summary and events.
7. The kill could land while the last PNGs were still being written. Fix: 2 s wait before Process.Kill.
8. If the script threw or was stopped with Ctrl+C mid-night, finally released both locks with the game still running. Fix: finally now ends the game it started (with -NoKill it prints a LEFT RUNNING warning instead). After a TIMEOUT the game is still left alone, as the rule says.
9. GameUserSettings.ini was written once for all nights; a game that exits by itself can rewrite it. Fix: written again before every night, restored at the end as before.
10. FightSec 300 was thin: with the fixed step the game is not tied to the wall clock and saves 5 PNGs per game second, so it can run slower than real time on a busy PC. Fix: defaults FightSec 480, BudgetSec 1200. This only costs time when a fight neither ends in a win nor in three knock-outs.
11. The log parser took any line containing "FTBRAWL ". Fix: only messages that start with it (": FTBRAWL ").
12. Smaller: sg.LandscapeQuality added to the quality list (the game's own preset has 11 groups); -FixedSeed added with the fixed step (steadies looks-only randomness such as blood spray); -OnScreen switch in case -brawlshots saves nothing under -RenderOffScreen; progress lines ("room is up after N s", "boss is in after N s"); a warning when the log has no Verbose lines; this night's old frames in the tag folder are still cleared before copying.
