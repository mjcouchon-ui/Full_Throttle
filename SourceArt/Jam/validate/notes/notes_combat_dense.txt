HOW A SCRIPT FIRES THE PLAYER'S WEAPONS
- Any autopilot (attract, -ftbench, -ftauto / FTAutoRun's bAutoDrive, or ft.Autopilot 1) throws the player's input away (In = FFTInput(), GM:~1115), holds the trigger (In.bFire = true, GM:1122) and launches a missile on the frame the race clock crosses a multiple of 1.7 s (In.bMissile = Fmod(Clock, 1.7) < Dt, GM:1130), if Missiles > 0 and the 0.3 s cooldown is over (GM:~1381-1384, log "FT MISSILES count=%d fired=1" GM:1383). So FTKey RightMouseButton / ft.Press / FTHold Fire do nothing while an autopilot drives.
- FTAutoRun sets bAutoRun, and then In.bFire and In.bMissile are forced false (GM:1177). Nothing ever clears bAutoRun on that game mode (only a map load), so it is "guns off for good".
- With no autopilot: FTHold Fire 1 (FLOW:1083-1087) and FTKey RightMouseButton 0.1 (FLOW:1156; the controller reads RightMouseButton as the missile) work, but nothing steers.
- FTFire <n> <Kind> (FLOW:1031) calls BulletHit directly: impact effects and damage, no muzzle flash, no tracer.
- Guns: one round every Stats.FireInterval = 0.085 s (FTGameMode.h:99), 1 damage for a standard round. Missiles: 6 at the start, cap 9 (FTGameMode.h:100); a crate gives +3 (GM:2459); FTPickup Crate with no arguments drops one on the car (FLOW:1068).
- Missile (GM:1777, tick GM:~2389-2436): lives 2.6 s; speed over the car 260 su/s rising 1500 su/s2 to 980 su/s (1 su = 13.71 cm, FTCore.h:14); homes on the foe ahead with the lowest 2|dx|+dy (never on civilians or barrels, but it does collide with them); on contact Explode 0.9, 9 damage (log "FT DAMAGE target=.. source=missile", GM:1815), splash 3 within 46 px; when its 2.6 s run out it bursts (Explode 0.6) with NO log line. A miss = a "fired=1" with no "source=missile" after it.

- Engine commands used instead (seen in K:\UE_5.9 source, non-Shipping): FX.DumpNCPoolInfo (NiagaraComponentPool.cpp:74; one line per system "Free: n | Used(Auto - Manual): a - m | System: .."), fx.Niagara.DumpComponents (NiagaraComponent.cpp:150; one line per component ending "is Active" / "is Inactive" / "Free In Component Pool"), obj list class=<Class> (UnrealEngine.cpp:8953), obj gc (UnrealEngine.cpp:8686; without it destroyed actors stay listed until the next collection, up to about a minute).
- FTTEL (GM:617, every 2 s while ft.Autopilot > 0) prints ents=<entity list length> and fps=<smoothed>.

FRAME TIME IN THE NORMAL RUN
- FTTEL fps=, FTHITCH ms= (every frame over 40 ms, GM:456), and the engine's StartFPSChart <label> / StopFPSChart (UnrealEngine.cpp:5741/5745; dumps to the log and to <Checkout>\Saved\Profiling\FPSChartStats\<time>\; t.FPSChart.OpenFolderOnDump 0 stops it opening an Explorer window, ChartCreation.cpp:48, 966). The normal run keeps the checkout's own frame cap unless t.MaxFPS 0 holds (the script sets it before PART 2).

BENCHMARK MODE + -ftexec, SO THE DENSE SCENE IS WHAT GETS TIMED
- -ftbench (GI:130-145): bBench, PendingLevel = -ftlevel (level INDEX, 7 = City Center), quality = -ftquality (default 2), seconds = -ftseconds (default 75), tag = -fttag; VSync off, frame limit 0; no attract mode; settings are not saved. The first map's BeginPlay opens the level's map and starts the race there (GM BeginPlay); the slate lasts 0.5 s; the bench autopilot is the same one (drives, shoots, a missile every 1.7 s) and armor is reset every frame.
- TickBench (GM:4116): BenchT counts real seconds (each frame capped at 0.1) in Play/Wreck/Wrap/Rating from the first frame of play of that game mode; frames are recorded once BenchT > 4; it ends when BenchT reaches seconds + 4, or at once if the level wraps; then it writes <Checkout>\Saved\FullThrottle\bench\bench_L7_EPIC<tag>.json, logs "FTBENCH {json}" (avg_fps, p1_low_fps, median_ms, p99_ms, worst_ms, frames_over_17_5ms, game/render/gpu ms) and quits the game itself. A restart on the spot does not reset BenchT.
- -ftexec runs beside it (the runner is in the game instance). The first script line runs on the first frame after the level's map is up, with the slate already showing. The "FT LEVEL id=" line is printed during the load, before the runner's log tap exists, so in bench mode a script must wait for FT SPEED, not FT LEVEL, and must not send FTStartLevel.
- combat_dense.txt itself is wrong for this (its stills, holds and 4 s run-in would be inside the sample). Use this script, which has the convoy up about 2.5 s into play, before sampling starts at 4 s:
    waitfor FT SPEED|300

    FTSpawn SUV 5

  (no quit: the benchmark quits). Command: jam_exec.ps1 -Tag <tag> -Script <that file> -Checkout <folder> -BudgetSec 900 -Extra "-ftnoattract -ftnodynres -ftslot=pie -ftbench -ftlevel=7 -ftquality=3 -ftseconds=10 -fttag=_dense". Sampling then covers seconds 1.5 to 11.5 of the same scene PART 2 times. -ftslot=pie makes it use the test career; run it after combat_dense.txt on that checkout (which resets that career and saves nothing else), because the car's stats are taken from the career at the race start, before any script line can run.

# Game level 8 (City Center), EPIC. Everything is done in the first seconds of scene 1, so a restart (which puts the

# Run it the same way on both checkouts (a new -Tag each run, the same frame size):
#   powershell -File "K:\Full Throttle\SkyScratch\SourceArt\Jam\unreal\jam_exec.ps1" -Tag <tag> -Script <this file>
#       -Checkout <project folder> -BudgetSec 1200 -Extra "-ftnoattract -ftnodynres"

# level 8 is written to the checkout's settings.json if the score beats the one stored there.

# TWO ROUNDS.
#  1 RETAKE : a missile that misses, a convoy, a missile that hits, wrecks by gun / missile / ram, barrels; the
#             car trashed, then wrecked (FTCrash) -> 2.8 s later the game's own retake (the same world goes on).
#  2 RESHOOT: a convoy, FTWrapNow (the boss is called 160 m ahead and wrecked, the wrap wrecks every vehicle), the
#             reel, THE DAILIES, R = reshoot -> PRE-PRODUCTION, READY -> the race restarts in the same world.
# After each restart the car's guns are off for good (FTAutoRun), so anything still burning is a leftover.
# Stills at 0.5 / 2 / 5 / 10 s after each restart. The slate covers the frame for the first 1.2 s at least; Enter is
# pressed at 1.4 s to drop it, so the 2 s and 5 s frames are clear (the 0.5 s frame is behind the slate).
# Round 1 also takes frames WITHOUT the HUD or the slate (ft.Shots 0.5): 1280x720, <Checkout>\Saved\Shots\
# ft_L7_000.png = about 0.8 s after the retake, then one every 0.5 s to about 5.3 s (ten frames; jam_exec does not
# collect or clear that folder: empty it before the run).

# THE COUNTS. The game has no line of its own for live effects. Each count block is six console commands:
#   obj gc                                   destroyed actors really go (otherwise they are listed for up to a minute)
#   FTDumpLevel                              "FT LEVEL dump ... take= retakes= clock="
#   FX.DumpNCPoolInfo                        LogNiagara: per effect "Free: n | Used(Auto - Manual): a - m | System: .."
#                                            Used = pooled effects playing now (explosions, flashes, impacts, trails)
#   obj list class=FTWreck                   burning wrecks alive (each carries a fire and a smoke effect)
#   obj list class=GeometryCollectionActor   barrel and crate debris alive
#   fx.Niagara.DumpComponents                LogNiagara: every effect component, "is Active" or "is Inactive"
# Blocks, by the runner's "FT EXEC line=<n>" numbers (the same in both runs): 0 pristine (slate up, nothing fired
# yet), 1 everything burning (the counts must be high here), 2 retake +5.9 s, 3 retake +10.5 s, 4 THE DAILIES,
# 5 reshoot +5.5 s, 6 reshoot +10.5 s. Clean = blocks 3 and 6 like block 0: no FTWreck, no GeometryCollectionActor,
# every "Used" 0 - 0, and the same number of "is Active" lines.
# In the log also: "result=timeout" (the script lost its place), "fired=1" (each missile launch) against
# "source=missile" (each missile hit: a launch with no hit after it was a miss).
