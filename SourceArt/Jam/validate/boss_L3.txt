# boss_L3.txt : THE BIG DEALER (game level 3, Nevada, level index 2), the whole fight, for before/after frames.
# Run (same line on both checkouts, same frame size, a new -Tag each time):
#   powershell -NoProfile -ExecutionPolicy Bypass -File "K:\Full Throttle\SkyScratch\SourceArt\Jam\unreal\jam_exec.ps1" -Tag bossL3_before -Script "K:\Full Throttle\SkyScratch\DevLog\jam\overhaul\validate\boss_L3.txt" -Checkout "K:\Full Throttle\OverhaulBaseline\full-throttle-unreal" -BudgetSec 900 -Extra "-ftnoattract -ftnodynres -ftslot=pie"
#   (-ftnoattract: a still title, nothing races behind it. -ftnodynres: fixed resolution. -ftslot=pie: the career
#   slot is the test slot from the first frame, whatever happens to the FTUseTestSlot line below.)
# After each run look in <checkout>\Saved\Logs\jam_exec_<tag>.log:
#   "result=timeout" must not appear (one timeout = the script lost its place, repeat the run),
#   "FT FIRE miss" and "LogFT: Error" must not appear,
#   "FT LEVEL id=L3 scene=8", three "FT BOSS state=Arrive armor=200 escape=90", "FT DAMAGE target=Boss .. left=" ending
#   at 190, 130, 64 and 0, three "source=DodgedJump", one "FT SPAWN kind=SnakeEyes .. add=1".
#
# HOW IT KEEPS ITS PLACE (line numbers = OverhaulBaseline, Source\FullThrottle)
# - Every boss timer runs on game time. So does the level clock, and "FT CLOCK level=<n>" is logged on the first
#   frame past each whole second (FTGameMode.cpp:1034). Each part starts on such a line, and FTBossNow / FTFire are
#   sent on one, so the boss's timers sit on the same grid as the clock:
#     boss summoned at clock N: T2=1.0 (FTGameMode.cpp:1665) -> bikes leave at N+1.0, then every 2.6 / 2.1 / 1.6 s
#     (phase 0 / 1 / 2, :2782); phase 1 or 2 entered at clock M: T3=min(T3,2.5) (:2773) -> brake check at M+2.5,
#     tail lights 0.8 s, then he drops back until 2.3 s (:2803-2808).
#   (T2 is set afresh each time, not carried over, so every bike adds up to one frame: the sixth bike of a boss is
#   0.05 s late at 60 frames a second and 0.15 s late at 20. The waits below allow for that.)
# - A "waitfor" only sees log lines written after the last console command (FTGameInstance.cpp:518, :552). So every
#   clock mark below must still be in the future when the FTFreeze 0 before it is sent. The script assumes 20 frames a
#   second or better; slower than about 12 and a mark is missed (result=timeout).
# - Stills: FTFreeze 1 / shot / FTFreeze 0 holds the world (time dilation 0.0001, FTGameMode.cpp:3735) while the frame
#   is written, so a still costs about 0.15 s of game time, and the waits between stills are game seconds.
# - The HUD's small plates run on the REAL clock, which the stills do not stop: the keys strip (first 10 s of play,
#   FTGameMode.cpp:1036), ACTION! (0.45 to 1.45 s after a scene change), the scene's name (2.8 s), a shout (1 s), a
#   caption (3 s) (FTHUD.cpp:650-717). The entrance stills are placed clear of those edges.
# - Hurting: "FTFire <n> Boss" = n standard rounds through the gun's real hit path in one frame, 1 armor each
#   (FTFlow.cpp:1031, BulletHit :150). Armor 200: 70 rounds -> 130 = 65 % = phase 1; 66 more -> 64 = 32 % = phase 2.
#   With FTAutoRun the car itself never fires (FTGameMode.cpp:1177), so nothing else moves his armor.
# - Defeat: FTWrapNow (FTFlow.cpp:1100) takes his remaining armor through the same path.
#

# ACTION! (FTGameMode.cpp:1036), which would otherwise fall in the middle of the entrance stills

# SpawnGroup: 16000 cm ahead, closing at 6000 cm/s until 9400 cm (1.1 s), then easing onto his spot at 5141 cm
# (FTGameMode.cpp:1660-1662, :2814). His first bike leaves once he is within 7641 cm, 1.5 s in (:2780).
# Stills at about 0.45 / 1.05 / 1.7 / 2.4 / 3.4 game seconds after "FT BOSS state=Arrive":
#   13300 cm away / 9800 / 6950 with the first bike on the ramp / 5850 / on his spot.
